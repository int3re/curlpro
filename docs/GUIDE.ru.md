# curlPro — полное руководство

*[English version](GUIDE.md)*

Вся библиотека в одном документе, для двух читателей: человека, который её
встраивает, и ИИ-ассистента, который изучает её перед тем, как трогать код.
Каждое число и каждое поведение здесь сверены с кодом 16 сентября 2026 года,
на версии 0.7.2. Где README говорит меньше, этот документ говорит больше; где
они расходятся, ошибается этот документ, и его надо поправить — скажите об этом.

Ассистенту, читающему это: библиотека уже делает почти всё, что скрапер пишет
руками. Раздел 15 перечисляет, что не нужно переписывать. Раздел 16 — какие
утверждения проверены и какие оказались ложью.

## 1. Что это, в трёх предложениях

curlPro — HTTP-клиент для Python, чей трафик несёт сетевой отпечаток браузера:
TLS ClientHello, кадры HTTP/2 и HTTP/3, набор, порядок и регистр заголовков,
рукопожатие WebSocket, даже границу multipart. Браузер описан JSON-профилем, а
не кодом, поэтому новая версия браузера — правка данных, доступная любому
пользователю прямо во время работы. Python-пакет — тонкий слой `ctypes` над
Go-библиотекой (uTLS для TLS, пропатченный fhttp для HTTP/1.1 и HTTP/2,
вендоренный uquic для HTTP/3), которая едет внутри колеса.

Всем, что ниже, управляют четыре правила. Они объясняют почти всё, что на
первый взгляд удивляет:

- **Профили — данные.** Браузер — это `.json`-файл; код общий. Если у браузера
  что-то меняется, меняется профиль, а не библиотека.
- **Измерено, а не предположено.** Значение попадает в профиль только после
  того, как его видели на проводе у настоящего браузера. Где ничего не
  измерено, библиотека говорит об этом, а не угадывает.
- **Отказать, а не проигнорировать.** Опция, которую нельзя выполнить,
  поднимает ошибку с причиной. Ничего не понижается, не отбрасывается и не
  подменяется молча.
- **Правда — на проводе.** `session.fingerprint()` и `session.audit()`
  считаются по байтам, которые ушли бы наружу, а не по конфигурации.

## 2. Установка и запуск

```bash
pip install curlpro
```

Колесо несёт нативную библиотеку и все 50 профилей; ни Go, ни компилятор C не
нужны. Колёса есть для Linux x86-64 и ARM64 (glibc 2.28+), macOS 13+ на Intel
и Apple Silicon и Windows x64; Python 3.9 и новее. Всё остальное собирается из
исходного архива с Go и компилятором C (`README.md`, «Install»).

Профили попадают в библиотеку тремя путями:

- **Из колеса, сами.** `ensure_loaded()` срабатывает на первом `Session`;
  вызывать ничего не нужно.
- **Из каталога.** `curlpro.load_profiles("profiles")` — так нужно в
  чекауте репозитория, где профили лежат рядом с пакетом, а не внутри него.
- **Во время работы.** `curlpro.register_profile(dict_or_json)` добавляет один
  профиль без релиза.

У нативной библиотеки есть версия ABI (`0.18` в этом релизе), которую Python
проверяет при импорте. Колесо всегда несёт согласованную пару; проверка нужна
для сборок из исходников и для `CURLPRO_LIBRARY`, которая указывает пакету на
вашу собственную библиотеку. Несовпадение поднимает ошибку при импорте с
командой пересборки в тексте.

Из чекаута на Windows: `.\build.ps1` пишет `dist/curlpro.dll`, затем
`cd python; $env:PYTHONPATH='.'; python -m pytest tests`.

## 3. Ментальная модель

Три слоя, каждый добавляет к нижнему:

| Слой | Владеет | Где задаётся |
|---|---|---|
| Профиль | отпечаток: TLS, HTTP/2, HTTP/3, наборы заголовков и их порядок, рукопожатие WebSocket, устройства | `profiles/*.json`, `register_profile()` |
| Сессия | память и политика: куки, добавленные заголовки, убранные заголовки, прокси, таймауты, ретраи, редиректы, устройство, режим | `curlpro.Session(...)` |
| Запрос | один обмен: тело, params, заголовки, порядок, протокол и любое переопределение политики сессии | `s.get(...)`, `s.request(...)` |

Запрос собирается так: заголовки профиля для выбранного набора (навигация или
fetch), потом заголовки сессии, потом заголовки запроса, потом шаблон порядка,
потом удаления. Результат — то, что показывает `fingerprint().headers`. Одна и
та же сборка обслуживает HTTP/1.1, HTTP/2 и HTTP/3 — правила существуют в
одном экземпляре.

## 4. Сессии: каждый параметр

`curlpro.Session(impersonate="chrome-151-windows", **options)`. У каждой опции
значение по умолчанию воспроизводит браузер; таблица говорит, что меняется,
когда вы её трогаете.

| Параметр | По умолчанию | Значение |
|---|---|---|
| `impersonate` | `chrome-151-windows` | имя профиля; `list_profiles()` знает все 50 |
| `verify` | `True` | `True` — системные корни; путь к PEM — доверять только ему; `False` — без проверки |
| `cert` | `None` | пути `(certificate, key)` для mTLS |
| `trust_env` | `True` | брать прокси из `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`, учитывая `NO_PROXY`; явный `proxy` всегда сильнее |
| `timeout` | `30.0` | предел на **весь** запрос, включая редиректы; пара `(connect, total)` отдельно ограничивает соединение. `float("inf")` — без предела |
| `connect_timeout` | `None` | предел на соединение по имени: резолв, TCP, TLS. Сильнее первого элемента пары |
| `response_timeout` | `None` | сколько ждать **заголовков** ответа после отправки запроса. Тело не ограничивает. Поднимает `Timeout` со словами «response headers» |
| `proxy` | `None` | `http://`, `https://`, `socks5://`, `socks5h://`, допустим `user:pass@`; голый `host:port` читается как `http://`. Первый CONNECT идёт без учётных данных и добавляет их после 407, как Chrome; прокси, который вместо этого рвёт соединение, получает второй CONNECT с ними на свежем соединении; тот, что рвёт и его, поднимает ошибку с кодом `proxy_closed` |
| `default_headers` | `True` | слать заголовки профиля. `False` шлёт только ваши — и вовсе без `User-Agent`, если вы его не передали; библиотека никогда не подставляет Go-шный |
| `header_order` | `None` | порядок отправки как шаблон с `...` вместо собственного порядка профиля; раздел 6 |
| `allow_redirects`, `max_redirects` | `True`, `20` | следовать 3xx; цепочка в `r.history` |
| `cookies` | `True` | банка, общая для запросов сессии |
| `force_http1` | `False` | предлагать в ALPN только `http/1.1`. Это меняет JA4 (два его символа), и законно: так выглядит браузер без h2 |
| `post_quantum` | `True` | `False` убирает X25519MLKEM768 и его key_share на 1216 байт: hello браузера с выключенным политикой постквантовым обменом. JA4 не меняется, JA3 и размер меняются, hello влезает в один TCP-сегмент |
| `resume` | `False` | возобновление TLS-сессии по билетам, кэш на сессию. Выключено, потому что возобновлённый hello не сверялся с оракулами |
| `http3` | `False` | идти в QUIC сразу. Профилю нужна секция `http3` (она есть у четырёх, раздел 12) |
| `alt_svc` | `True` | переходить на HTTP/3 после заголовка `Alt-Svc`, как браузер; неудачная попытка откатывается на TCP и не повторяется 5 минут, с удвоением до 24 часов. Нужна секция `http3`; через прокси не работает |
| `resolve` | `None` | `{"example.com:443": "10.0.0.7"}` — `--resolve` из curl; SNI и `Host` сохраняют имя. Через прокси не работает |
| `ip_version` | `None` | `"4"` или `"6"` — одно семейство адресов |
| `keep_alive` | `True` | переиспользовать соединения. `False` закрывает после каждого ответа, не посылая `Connection: close` |
| `max_idle_conns`, `idle_conn_timeout` | `0`, `0.0` | размер пула и время жизни простаивающего соединения; ноль — умолчания библиотеки |
| `retries` | `0` | попытки после первой. Повторяются только идемпотентные методы, если `retry_methods` не скажет иначе |
| `retry_statuses` | 408, 429, 500, 502, 503, 504 | какие ответы считаются сбоем, который стоит повторить |
| `retry_methods` | идемпотентные | GET, HEAD, PUT, DELETE, OPTIONS, TRACE; явный список разрешает POST |
| `retry_backoff`, `retry_max_backoff` | `0.2`, `10.0` | секунды; экспонента между ними |
| `respect_retry_after` | `True` | заголовок `Retry-After` задаёт ожидание |
| `mode` | `"auto"` | набор заголовков: `navigate`, `fetch` или выбор по запросу (раздел 7) |
| `device`, `devices` | `None` | телефон для мобильных профилей — имя из списка профиля или `"random"` — и свой список (раздел 11) |
| `max_response_size` | `0` | предел тела в байтах; превышение поднимает ошибку с кодом `too_large`. Ограничивает `read()`, не `iter_content()` |
| `hooks` | `None` | `{"request": [...], "response": [...], "error": [...]}`; раздел 9 |

Атрибуты сессии, которые стоит знать: `s.headers` (отображение добавленных вами
заголовков плюс `s.headers.suppressed`), `s.cookies` (раздел 10), `s.hooks`,
`s.impersonate`, `s.fingerprint(url="https://example.com/")`, `s.audit()`,
`s.close()`. Сессия — контекстный менеджер; `__del__` тоже закрывает её.

## 5. Запросы: каждый параметр и ответ

`s.request(method, url, **kw)`, с сокращениями `get`, `post`, `put`, `patch`,
`delete`, `head`, `options`. Модульные `curlpro.get(url, impersonate=...)` и
собратья открывают сессию на один запрос. Всё, что задано на сессии, здесь можно
переопределить для одного запроса; `None` значит «как у сессии».

| Параметр | Значение |
|---|---|
| `params` | строка запроса, отображение или пары, вливается в URL |
| `auth` | `("user", "password")` для Basic или строка как bearer-токен |
| `data` | тело как bytes или str |
| `json_body` | любое JSON-сериализуемое значение; ставит `content-type: application/json`, если вы не поставили |
| `fields` | форма; одна — `application/x-www-form-urlencoded`, с `files` — multipart |
| `files` | файлы multipart; граница генерируется в стиле профиля (`----WebKitFormBoundary…` у Chrome, дефисы у Firefox) |
| `body_file` | путь, который потоком идёт телом с явным `Content-Length`; браузер никогда не грузит файл chunked |
| `headers` | ваши заголовки. Значение `None` **убирает** заголовок, который послали бы профиль или сессия; `""` шлёт его пустым. Всё, кроме `str` и `None`, — `TypeError` с именем заголовка |
| `header_order` | шаблон порядка для этого запроса, сильнее сессионного (раздел 6) |
| `default_headers` | `True`/`False` — заголовки профиля, в обе стороны, для этого запроса |
| `session_headers` | `False` — без заголовков и удалений, заданных на сессии |
| `cookies` | `False` — не слать банку и не запоминать `Set-Cookie`; двусторонне намеренно |
| `protocol` | `"http1"`/`1.1`, `"h2"`/`2`, `"h3"`/`3`. `h2` оставляет полный список ALPN и **падает**, если сервер выбрал `http/1.1` (ни один браузер не предлагает h2 в одиночку); `h3` требует TLS; поверх `http://` оба отклоняются |
| `timeout`, `connect_timeout`, `response_timeout` | как на сессии, для этого запроса |
| `proxy` | адрес, либо `False` — напрямую, в обход прокси сессии |
| `allow_redirects`, `max_redirects`, `retries`, `retry_*`, `respect_retry_after` | переопределения политики сессии; `retries=0` выключает ретраи сессии для этого запроса |
| `mode` | `"navigate"` или `"fetch"`; `fetch` на профиле без набора fetch отклоняется с причиной |
| `expect` | `Expect(...)`; несовпадение поднимает `ExpectationFailed` (раздел 8) |
| `rollback_cookies` | `True` возвращает банку к состоянию до запроса, если запрос не удался, включая проваленное ожидание |

Ответ:

| Член | Значение |
|---|---|
| `status`, `ok`, `proto` | `200`, `status < 400`, `"HTTP/1.1"` / `"HTTP/2.0"` / `"HTTP/3.0"` |
| `headers` | `dict[str, list[str]]` — каждое значение каждого заголовка |
| `header(name)` | первое значение без учёта регистра или `None` |
| `content`, `text` | байты; str, декодированная найденной кодировкой |
| `encoding` | из `Content-Type`, потом BOM, потом `<meta charset>` в первых килобайтах; присваиваемо, когда сайт объявляет её неверно |
| `json()` | `json.loads` по сырым байтам — UTF-8/16/32 парсер узнаёт сам |
| `url` | конечный URL после редиректов |
| `history` | цепочка редиректов как записи `Redirect(status, url, location)` |
| `cookies` | куки, которые поставил **этот** ответ, как отображение |
| `elapsed` | секунды, измеренные в Python вокруг нативного вызова |
| `raise_for_status()` | поднимает `HTTPError` (с `.status` и `.response`) на 4xx/5xx; иначе возвращает ответ |

Тела приходят распакованными: `gzip`, `deflate` (zlib или сырой), `br` и
`zstd`, в любом порядке наложения, который использовал сервер. Распаковывать
самому нечего.

Редирект с `https://` на `http://` не выполняется: 3xx возвращается с его
`Location`, потому что переход отправил бы куки и учётные данные открытым
текстом. Сам открытый `http://` работает — с порядком и регистром заголовков
HTTP/1.1 из профиля, потому что это всё, что видит собеседник по plain HTTP.

## 6. Заголовки: набор, порядок, удаления

**Набор** приходит из профиля и зависит от режима (раздел 7). Ваши заголовки
ложатся сверху: имя, которое профиль уже шлёт, сохраняет позицию и берёт ваше
значение; новое имя встаёт туда, куда браузер поставил бы кастомный заголовок —
перед якорем профиля, а не в конец.

**Удаление** — это `None`: `headers={"Sec-Fetch-User": None}` для одного
запроса, `s.headers["Sec-Fetch-User"] = None` для каждого запроса сессии.
Остальной набор не трогается. `""` — значение, оно уходит пустым заголовком,
как шлёт его браузерный `fetch()`. Значение запроса сильнее удаления на
сессии; `del s.headers[name]` и `s.headers.clear()` снимают удаления так же,
как убирают значения; `s.headers.suppressed` их перечисляет.

**Порядок** — шаблон поверх порядка браузера, на сессии или на запросе. `...`
означает «здесь собственные заголовки профиля»:

```python
s.get(url, headers={"X-Api-Key": "k"},
      header_order=[..., "accept", "x-api-key", ...])   # сразу после Accept, остальное как есть
s.get(url, header_order=["x-api-key", ...])            # первым
s.get(url, header_order=[..., "x-api-key"])            # последним
s.get(url, header_order=[..., "accept-encoding", "accept-language", ...])   # два заголовка профиля местами
```

Правила: `...` может быть несколько, и не названный заголовок профиля остаётся
рядом с названным соседом, за которым идёт в профиле; список без `...` — это
список, а за ним остаток профиля; имена, которых в запросе нет, пропускаются,
так что один шаблон подходит всем запросам; имя дважды отклоняется; кастомный
заголовок, которого шаблон не называет, по-прежнему встаёт перед якорем.
Раскрытие идёт по порядку реально используемого транспорта — у HTTP/1.1 есть
`Host` и `Connection` и свой регистр, у HTTP/2 нет ни того, ни другого, —
поэтому `fingerprint().headers` и `headers_http1` показывают ровно то, что
уйдёт.

`default_headers=False` — грубый инструмент: он убирает весь набор профиля,
включая `User-Agent`, и порядок вместе с ним. С 0.7.0 он редко нужен; `None`
убирает один заголовок и сохраняет остальные.

## 7. Навигация и fetch

Браузер шлёт разные наборы заголовков при переходе на страницу и при `fetch()`
или XHR со страницы. У набора fetch `accept: */*`, `sec-fetch-mode: cors`,
`sec-fetch-dest: empty`, `Origin`, `Referer` и нет `upgrade-insecure-requests`
и `sec-fetch-user`. Каждый профиль Chromium, Firefox, Tor и Yandex несёт оба
набора, измеренные (Chrome 152 и Firefox 154 на сыром стенде); Safari и okhttp
несут только навигационный.

В `mode="auto"` (по умолчанию) решает сам запрос, и любое из этого значит
fetch:

- метод, отличный от GET, HEAD и POST;
- тело, которое не форма — JSON, XML;
- заголовок, которого навигационный набор не несёт никогда — любой кастомный
  `X-…`, `Authorization`;
- значение fetch-метаданных, которого у навигации не бывает:
  `sec-fetch-mode: cors`, `sec-fetch-dest: empty`.

Поэтому `s.get(url, headers={"X-Api-Key": "k"})` уходит как fetch — так делает
браузер с кастомным заголовком. Когда вам это не подходит, скажите
`mode="navigate"`. Явный `mode="fetch"` на профиле без набора fetch отклоняется
с причиной: навигационный набор под именем fetch — `sec-fetch-user: ?1` рядом с
`sec-fetch-mode: cors` — запрос, которого не делает ни один браузер, и антибот
читает эту пару даром.

## 8. Ожидания и откат кук

```python
from curlpro import Expect

r = s.get(url, expect=Expect(status=200, body="Dashboard", not_body="captcha",
                             non_empty=True, encoding="utf-8"))
```

| Поле | Проверяет |
|---|---|
| `status`, `not_status` | код; несколько значений — «один из» |
| `body`, `not_body` | подстроки в теле; несколько — «все» |
| `headers`, `not_headers` | подстроки среди строк `name: value`, без учёта регистра |
| `non_empty` | тело не пустое |
| `json` | тело разбирается как JSON |
| `encoding` | найденная кодировка — эта; `cp1251` и `windows-1251` равны |

Несовпадение поднимает `ExpectationFailed` (код `expectation`), это
`CurlProError` с приложенным ответом. Проверка идёт после хуков ответа, по тому,
что они вернули.

`rollback_cookies=True` на запросе или `with s.cookies.transaction():` вокруг
нескольких возвращает банку, если блок поднял исключение — полузавершённый
логин хуже, чем никакого. Снимок делается до отправки; откат происходит до
хуков ошибки, так что хук, идущий в сеть, видит банку такой, какой она была.

## 9. Ошибки и хуки

```python
try:
    r = s.get(url)
    r.raise_for_status()
except curlpro.Timeout:                  # код "timeout"
    ...
except curlpro.ExpectationFailed as e:   # код "expectation", e.response сохранён
    ...
except curlpro.HTTPError as e:           # из raise_for_status(): e.status, e.response
    ...
except curlpro.WebSocketClosed:          # код "ws_closed"
    ...
except curlpro.CurlProError as e:        # всё остальное: e.code, str(e)
    ...
```

`CurlProError` — это `RuntimeError`; четыре выше наследуются от него. Ветвитесь
по типу или по `code`, никогда по тексту — тексты написаны для людей и свободно
правятся. Коды: `timeout`, `expectation`, `session_closed`, `too_large`,
`ws_closed`, `ws_too_big`, `ws_protocol`, `proxy_closed`. Ошибка без кода —
обычный сбой с причиной в тексте.

Три хука, каждый — список вызываемых в `s.hooks[...]`, добавляются и через
`@s.on_request`, `@s.on_response`, `@s.on_error`:

- **request** получает описание запроса — словарь с `method`, `url`, `headers`
  и остальным кадром — до отправки; может править его на месте или вернуть
  замену.
- **response** получает `Response` после прихода и может вернуть замену;
  ожидание проверяется по замене.
- **error** получает исключение неудавшегося запроса (сеть, таймаут,
  проваленное ожидание) и может вернуть исключение, которое поднять вместо
  него. Хук, который сам упал, не прячет исходный сбой: сбой отмечается на
  исключении, а остальные хуки всё равно выполняются.

## 10. Куки

`s.cookies` — отображение по имени для чтения и полная банка под ним:

| Вызов | Делает |
|---|---|
| `s.cookies["sid"]`, `.get`, `.keys`, `.items`, `.values` | значения |
| `.all()` | полные записи как словари `Cookie`: name, value, domain, path, expires (секунды эпохи, 0 у сессионной), флаги |
| `.set(name, value, *, domain, path="/", expires=0, secure=False, http_only=False, same_site="")` | добавляет одну; домен обязателен |
| `.load(list)`, `.export()` | простые записи внутрь и наружу |
| `.save(path)`, `.load_file(path)` | JSON; `load_file` читает и Netscape `cookies.txt`, распознавая по содержимому, а отсутствующий файл считает пустым первым запуском |
| `.save_netscape(path)`, `.load_netscape(path)`, `.to_netscape()` | тот `cookies.txt`, который используют curl, wget, yt-dlp и браузерные расширения |
| `.snapshot()`, `.restore(snapshot)`, `.transaction()` | механика отката |
| `.clear()` | забыть всё |

`r.cookies` у ответа — только то, что поставил этот ответ.

## 11. Профили, устройства и мобильные

В колесе 50 профилей: 25 Chrome (с 98 по 152), 6 Edge, 4 Firefox (133, 135,
144, 155), 11 Safari (с 15.3 по 26.0.1, macOS и iOS), Tor 14, Яндекс Браузер
26.8 для Android и два okhttp 5.5 (JVM и Conscrypt). Многие делят один
TLS-отпечаток: 50 профилей образуют 17 разных значений JA4, потому что
семейство браузера сохраняет ClientHello несколько версий подряд и отличается
User-Agent и заголовками. Одна группа — Chrome с 119 по 131 и Edge 119/120,
последние hello Chromium до постквантового key_share — на части соединений
показывает второе написание JA4 (`…1517…` рядом с `…1516…`): её hello стоит
около 512 байт, и расширение padding появляется или нет вместе со случайным
размером GREASE-полезной нагрузки ECH, ровно как у самих браузеров. Эталоны
перечисляют оба. `list_profiles()` называет их все.

Что несёт каждое семейство, с учётом наследования:

| Семейство | Навигационный набор | Набор fetch | Набор HTTP/1.1 | WebSocket | HTTP/3 |
|---|---|---|---|---|---|
| Chrome, Edge, Yandex | да | да | да | да | chrome-151-windows, chrome-152-windows, chrome-152-android, yandex-26.8-android |
| Firefox, Tor | да | да | да | да | нет |
| Safari | да | нет | да | нет | нет |
| okhttp | да | нет | нет | нет | нет |

**Мобильные.** `chrome-152-android` и `yandex-26.8-android` несут пул из 46
настоящих телефонов — точные строки `ro.product.model` из каталога устройств
Google Play на правдоподобных версиях Android. `device="Pixel 8"` или
`device="random"` выбирает один на сессию. У Chrome модель едет в client hints
`sec-ch-ua-model` и `sec-ch-ua-platform-version`, которые уходят только после
того, как сайт попросил их через `Accept-CH` (и сразу при `Critical-CH`);
User-Agent остаётся `Android 10; K`, как у Chrome. Яндекс пишет модель прямо в
User-Agent, так что там пул — 46 разных строк. Свой список передаётся в
`devices=[{"name": ..., "model": ..., "platform_version": ...}]`. Имя не из
списка отклоняется.

**Наследование.** Профиль может назвать `based_on`; тогда он хранит только свои
отличия. Chrome 110 поверх Chrome 98 — одна строка: включить перемешивание
расширений. `Profile.from_file(path).derive("chrome-153-windows",
headers={...}).register()` делает дельту из Python; `register_profile()`
принимает dict, JSON-строку или bytes. Схема — в `docs/PROFILE-SCHEMA.md`.

**Захват браузера** — Go-команда, не часть колеса: `go build ./cmd/curlpro`,
затем `curlpro capture -name firefox-155-windows` поднимает стенд, ведёт
установленный браузер, сворачивает несколько образцов в профиль и даёт полному
профилю наборы HTTP/1.1, fetch и WebSocket его семейства. `validate`, `diff`,
`collapse` и `list` — остальные подкоманды; метод и грабли — в
`docs/CAPTURE.md`.

## 12. Транспорты: HTTP/1.1, HTTP/2, HTTP/3, WebSocket

Между HTTP/1.1 и HTTP/2 выбирает сервер через ALPN из списка, который предлагает
профиль; `force_http1` сужает предложение. У каждого транспорта свой набор
заголовков из профиля: HTTP/1.1 добавляет `Host` и `Connection` и использует
регистр браузера; Chrome не шлёт там `priority`, а Firefox — `TE`.

HTTP/3 включается как у браузера — сначала TCP, потом QUIC после заголовка
`Alt-Svc` — или сразу через `http3=True`; `protocol="h3"` заставляет один
запрос. Транспортные параметры QUIC, SETTINGS, GREASE-кадр и порядок заголовков
берутся из секции `http3` профиля, сверенной с `quic.browserleaks.com`. Секция
есть у четырёх профилей (раздел 11).

WebSocket: `with s.websocket(url, headers=None, subprotocols=None, timeout=30.0,
max_message_size=0) as ws`. Заголовки рукопожатия берутся из шаблона
`websocket` профиля — набор и порядок, которые шлют Chrome и Firefox, включая
`permessage-deflate`. `ws.send(str | bytes)` выбирает тип кадра по данным,
`ws.recv()` возвращает `str` или `bytes`, `ws.ping()`, `ws.close(code=1000,
reason="")`, а `for message in ws` читает, пока сервер не закроет
(`WebSocketClosed`). `timeout` — предел тишины на чтении (код `timeout`,
соединение остаётся рабочим); `max_message_size` поднимает `ws_too_big`.
Открытый `ws://` тоже работает.

## 13. Потоки, загрузки, async

```python
with s.stream("GET", url) as r:                 # те же аргументы, что у request()
    for chunk in r.iter_content(64 * 1024):
        out.write(chunk)
    for line in r.iter_lines():                 # NDJSON и подобное
        ...
```

Поток держит соединение до закрытия, отсюда `with`. `r.read()` собирает
остаток и ограничен `max_response_size`; `iter_content()` — нет, намеренно.
Закрытие с непрочитанным телом рвёт соединение, а не дочитывает. Загрузки идут
потоком через `body_file=path`.

`AsyncSession` принимает те же аргументы, что `Session`, и предлагает те же
методы как корутины: `await s.get(...)`, `async with s.stream(...) as r: async
for chunk in r.iter_content()`, `async with s.websocket(url) as ws`. Запрос — это
горутина на нативной стороне; процесс держит один поток, и цикл событий никогда
не блокируется. Отменённая задача отменяет запрос нативно. `s.cookies`,
`s.headers` и хуки — те же, что у синхронной сессии.

## 14. Отпечаток, аудит и персоны

`s.fingerprint(url="https://example.com/")` считает, ничего не отправляя, что
увидел бы сервер:

| Поле | Значение |
|---|---|
| `ja4`, `ja4_r` | JA4 и его читаемая форма — стабильны между соединениями и доменами; это значение для сравнения |
| `ja3n`, `ja3`, `ja3_text` | JA3 с отсортированными расширениями (стабилен) и обычный JA3, который **плавает** между соединениями у Chrome ≥110, потому что расширения перемешиваются |
| `akamai` | отпечаток HTTP/2: SETTINGS, window update, priority, порядок псевдозаголовков |
| `ciphers`, `extensions`, `curves`, `sigalgs`, `alpn` | сырые списки без GREASE, в порядке отправки |
| `headers`, `headers_http1` | имена заголовков, которые ушли бы у обычного GET, по HTTP/2 и по HTTP/1.1 |
| `ja4h`, `ja4h_http1`, `ja4h_available` | отпечаток запроса; пуст с `ja4h_available == False` в сборке с `-tags nofoxio` |
| `user_agent`, `profile` | строка, которая ушла бы, и имя профиля |
| `client_hello` | собранный ClientHello байтами; `len()` отвечает, влезает ли он в один TCP-сегмент |
| `to_dict()`, `diff(other)`, `==` | всё как данные; разница по полям (расширения сравниваются как множества, `ja3` и `client_hello` исключены) |

Значения сверены с 50 живыми захватами в `reference/baselines`: JA4, JA3N и
строка Akamai совпадают с оракулом на каждом. Собственные опции сессии
учитываются — `force_http1` и `post_quantum=False` меняют hello, и отпечаток
показывает тот hello, который эта сессия шлёт.

`s.audit()` ищет противоречия внутри личности — причину, по которой правильный
отпечаток всё равно ловят. У каждого `Finding` есть `code`, `level` (`high`,
`medium`, `low`), `what`, `why`, `fix`. Проверки консервативны; стоковый
профиль молчит, кроме телефонного профиля без выбранного устройства:

| Код | Уровень | Срабатывает, когда |
|---|---|---|
| `tor_language` | high | профиль Tor шлёт любой `accept-language`, кроме `en-US,en;q=0.5` |
| `ua_version` | high | версия в User-Agent расходится с версией профиля (Chrome, Edge, Firefox) |
| `ua_family` | high / medium | User-Agent другого браузера или вовсе без браузера |
| `platform` | high | `sec-ch-ua-platform` расходится с User-Agent |
| `mobile_no_device` | medium | профиль со списком устройств и без выбранного |
| `navigation_headers_on_fetch` | high | `sec-fetch-user` или `upgrade-insecure-requests` рядом с fetch-метаданными, говорящими «fetch» |
| `accept_encoding` | medium | `accept-encoding` не как у профиля или его нет вовсе |
| `no_user_agent` | high | нет User-Agent вообще — то, что оставляет `default_headers=False` |

`Persona` связывает одну личность — профиль, прокси, устройство, заголовки
(включая удаления), куки, произвольные `notes` — с одним JSON-файлом:

```python
p = curlpro.Persona.new("chrome-152-windows", proxy="socks5h://user:pw@host:1080",
                        headers={"Accept-Language": "de-DE,de;q=0.9"})
p.save("accounts/user42.json")

p = curlpro.Persona.load("accounts/user42.json")
with p.session(timeout=20) as s:       # переопределения уходят в Session; куки восстановлены
    s.get("https://example.com/")     # забираются на выходе, даже если блок упал
p.save()                              # атомарная запись; усечённый файл при загрузке отклоняется
```

`p.open()` возвращает обычную сессию, `p.capture(s)` забирает куки сессии, не
закрывая её, `p.fingerprint()` и `p.audit()` работают без сети,
`load_all(directory)` перебирает папку персон. Персона ничего не ротирует: какую
личность брать и когда её списывать — политика вызывающего.

## 15. Что не нужно переписывать

Ассистенту, которого просят добавить что-то из этого в код, уже использующий
curlPro, стоит взять готовое. Каждая строка его называет:

- **Распаковка** `gzip`, `deflate`, `br`, `zstd`, наложенных в любом порядке — `r.content` уже распакован.
- **Определение кодировки** — `r.text` и `r.encoding` следуют браузерному порядку: заголовок, BOM, документ.
- **Редиректы** с историей и отказом https→http — `allow_redirects`, `r.history`, `r.url`.
- **Ретраи** с экспоненциальной паузой, `Retry-After` и идемпотентностью — `retries=`, `retry_statuses=`, `retry_methods=`.
- **Хранение кук**, `cookies.txt`, откат — `s.cookies.save/load_file`, `transaction()`, `rollback_cookies=`.
- **Порядок и регистр заголовков** — профиль, плюс `header_order=[..., ...]` для правок; никогда не собирайте списки заголовков руками.
- **Удаление заголовка** — `None`, а не `default_headers=False`.
- **Наборы fetch и навигации** — `mode`, выбирается сам.
- **Client hints и модели телефонов** — `device=`, `devices=`, уже отвечают на `Accept-CH` и `Critical-CH`.
- **Прокси** с переменными окружения, SOCKS5 с удалённым DNS, аутентификация CONNECT — `proxy=`, `trust_env`.
- **HTTP/3** с `Alt-Svc` и откатом — включён по умолчанию там, где у профиля есть секция.
- **WebSocket** с рукопожатием браузера и `permessage-deflate` — `s.websocket()`.
- **Потоковые** загрузки и выгрузки — `s.stream()`, `body_file=`.
- **Проверка ответа** — `Expect(...)` вместо самописных цепочек `if`.
- **Файлы личностей** — `Persona`, а не самодельный JSON из прокси и кук.
- **Проверка отпечатка** — `s.fingerprint()` и `s.audit()` офлайн, а не обращение к оракулу.
- **Прослойка под `requests`** — `import curlpro.requests as requests` уже есть; неподдерживаемые аргументы поднимают ошибку, а не игнорируются.
- **Новая версия браузера** — дельта профиля или `register_profile()`, а не правка библиотеки.

## 16. Проверенные утверждения: что было ложью, что правда

Всё в этом руководстве сверено с кодом, профилями и набором тестов 16 сентября
2026 года. Ревизия старых документов нашла ложными эти утверждения, и они
исправлены в том же релизе:

- README говорил, что документация проекта написана по-русски, а английский
  файл — её двойник. Ложь с 8 сентября 2026: оригинал английский, а
  `README.ru.md` — двойник; тест держит их структуру в согласии.
- Список кодов ошибок в README не содержал `too_large` и `proxy_closed`,
  которые нативная сторона поднимает с 0.3 и 0.5.2 соответственно.
- Абзац о лицензиях в README называл fhttp MIT; он под BSD-3-Clause, как
  говорит `NOTICE`.
- `ARCHITECTURE.md` называл текущим релизом 0.4.2.
- `curlpro.request(method, url)` был описан по форме, но не экспортирован;
  теперь экспортирован.

Факты, в которых легко усомниться и которые верны:

- Chrome ≥110 перемешивает TLS-расширения на каждом соединении, поэтому `ja3`
  плавает, а `ja4` и `ja3n` стоят. Это правильное поведение, а не дефект.
- ClientHello современного браузера — ~1,9 КБ из-за постквантового key_share
  и занимает два TCP-сегмента. Профили это воспроизводят, а
  `post_quantum=False` — ручка для проверки путей, которым это не нравится.
- Firefox 155 шлёт три key_share (X25519MLKEM768, x25519, secp256r1); профиль
  воспроизводит сырой hello, снятый с живого браузера.
- postman-echo.com стоит за Cloudflare, который переписывает `Accept-Encoding`
  в `gzip, br` до того, как origin его отдаст. Судите о заголовках по сырому
  стенду (`python/tests/rawserver.py`), а не по публичному эхо.
- Любой кастомный заголовок переключает запрос на набор fetch в режиме `auto`.
  Так делает браузер; `mode="navigate"` говорит иначе.
- `timeout` ограничивает весь запрос, а не тишину между байтами, как в
  `requests`. Перенесённое значение безопасно: строже, а не мягче.
