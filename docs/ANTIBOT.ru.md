# Защиты от ботов: как их узнать и как пройти

English version: [ANTIBOT.md](ANTIBOT.md).

curlPro встречает антиботы на трёх уровнях, и этот документ — обо всех трёх:

1. **Не попасть под проверку.** Запрос, у которого ClientHello TLS, кадры
   HTTP/2, порядок заголовков и client hints — как у настоящего браузера, даёт
   воротам меньше поводов. Этим занята вся остальная библиотека
   ([GUIDE.ru.md](GUIDE.ru.md)); здесь это причина, по которой многие запросы
   до ворот вообще не доходят. На nowsecure.nl — странице, сделанной для
   проверки Cloudflare, — самому curlPro страницу отдали без всякой проверки.
2. **Знать, что тебя остановили, и кто.** `r.challenge` говорит, какой вендор
   ответил и что это за ответ: проверка, капча, блокировка, лимит частоты или
   запрос, который вендор не смог прочитать.
3. **Пройти.** Проверку выполняет настоящий браузер, её никто не
   переписывает: `BrowserSolver` проходит её в Chrome, установленном на машине,
   и отдаёт сессии куки; свой решатель встаёт на то же место.

Совпадение сетевого отпечатка необходимо, но не достаточно: антиботы смотрят
ещё на поведение, репутацию IP и то, что страница измеряет в браузере. curlPro
закрывает сетевой уровень, а браузерный отдаёт браузеру. **Ничто в пакете не
отправляет проверку в сервисы решения капч** — и не будет.

## За тридцать секунд

```python
import curlpro

# Узнать: каждый ответ говорит, не ответ ли это антибота.
with curlpro.Session("chrome-154-windows") as s:
    r = s.get("https://example.com/")
    if r.challenge:                        # None для обычного ответа
        print(r.challenge.vendor, r.challenge.kind, r.challenge.solvable, r.challenge.evidence)
    r.raise_for_challenge()                # ChallengeError (code "challenge"), если это он

# Пройти: проверка проходится в установленном Chrome, запрос повторяется.
solver = curlpro.BrowserSolver()
with curlpro.Session(**solver.session_options(), solver=solver) as s:
    r = s.get("https://example.com/")      # сама страница, за проверкой
```

## 1. Что лежит в `r.challenge`

`None` или `Challenge`:

| Поле | Значение |
|---|---|
| `vendor` | `cloudflare`, `qrator`, `datadome`, `human` (PerimeterX), `akamai`, `imperva` (Incapsula), `kasada` |
| `kind` | что это за ответ — таблица ниже |
| `solvable` | поможет ли решатель: да для `challenge` и `captcha` |
| `status` | HTTP-статус ответа |
| `url` | URL, который ответил |
| `ray` | идентификатор запроса Cloudflare (`cf-ray`), тот, что просит их поддержка; в остальных — `""` |
| `evidence` | сработавшие метки строками — `("cf-mitigated: challenge",)`, `("x-qrator-validate-result: captcha", "x-qrator-token", ...)` |

| `kind` | Что значит | `solvable` | Что делать |
|---|---|---|---|
| `challenge` | проверка, которую браузер выполняет и проходит сам: управляемые и JS-проверки Cloudflare, Turnstile перед страницей, 401 Qrator, интерстишелы Akamai и Imperva, Kasada | да | `BrowserSolver` или свой решатель |
| `captcha` | проверка, которой может понадобиться человек: чекбокс Turnstile, слайдер DataDome, «нажми и держи» HUMAN, картинка и чекбокс Qrator | да | `BrowserSolver` с его окном (чекбокс Turnstile нажимается сам, остальное ждёт человека) или свой решатель |
| `block` | решение уже принято: 1020 Cloudflare, «Access Denied» Akamai, страница инцидента Imperva, DataDome без капчи | нет | никакой браузер этого не изменит — другой адрес, медленнее темп, другой запрос |
| `rate-limit` | слишком много запросов: 1015 Cloudflare | нет | сбавить темп; с включёнными повторами (`retries=3` — по умолчанию они выключены) `Retry-After` у 429 задаёт паузу |
| `no-verdict` | антибот не смог прочитать присланное: эндпоинт проверки Qrator ответил голым 403 | нет | запрос собран неверно — сравнить его с браузерным (раздел 4) |

`r.raise_for_challenge()` бросает `ChallengeError` на любой из них, с
`.challenge` и ответом в `.response`; `e.code == "challenge"`.

Ответ читается при первом обращении к `r.challenge` и запоминается.
Просматриваются только первые 64 КиБ тела: любая страница проверки называет
вендора в своём `<head>`. У потокового ответа (`s.stream(...)`) `.challenge`
тоже есть — по одним заголовкам, тело ещё не пришло.

## 2. Вендоры и как именно узнаётся каждый

Кроме заголовка Cloudflare и собственных статусов Qrator, ответ разбирается,
только если статус 403, 429 или 503: 200 с виджетом капчи — это страница,
которая просит капчу в своей форме, а не ворота перед страницей.

| Вендор | Узнаётся по | Откуда правило |
|---|---|---|
| Cloudflare | `cf-mitigated: challenge` на любом статусе; его страницы за `Server: cloudflare` / `cf-ray` | документация вендора; замерено на стенде проекта |
| Qrator | его 401 с `qrator_jsr`; вердикт `X-Qrator-Validate-Result` | снято на проводе с `login.mts.ru` полевым отчётом |
| DataDome | заголовок `x-datadome`; `captcha-delivery.com` вместе с кукой `datadome` | метки, которые известны у его страниц |
| HUMAN | `_pxAppId` или `px-captcha` на странице | то же |
| Akamai | интерстишел `sec-if-cpt-container`; `AkamaiGHost` с «Access Denied» | то же |
| Imperva | `_Incapsula_Resource`; «Incapsula incident ID» | то же |
| Kasada | 429 с заголовками `x-kpsdk-*` | то же |

Последние пять на стенде проекта не замерялись. Каждый `Challenge` пишет в
`evidence`, что совпало, так что ошибку видно, — а отчёт о ней, как отчёт о
Qrator, и есть способ поправить правило.

### Cloudflare

| Ответ | `kind` |
|---|---|
| `cf-mitigated: challenge`, любой статус, тело не нужно | `challenge` |
| 403/429/503 от Cloudflare с `/cdn-cgi/challenge-platform/` или `_cf_chl_opt` на странице | `challenge` |
| «error code: 1015» или 429, страница которого называет Cloudflare | `rate-limit` |
| `cf-error-details`, «Sorry, you have been blocked», «error code: 10…» | `block` |

`cf-mitigated` — заголовок, который Cloudflare документирует ровно для этого
(«Detect a challenge page response»), поэтому проверка на API-вызове — 403 с
заголовком и ничем, что браузер стал бы рисовать, — узнаётся по одним
заголовкам. В `ray` — `cf-ray`.

**Готовое решение:** `BrowserSolver`. Кука прохода — `cf_clearance`; запрос
повторяется в момент её появления. Чекбокс Turnstile, если он его просит,
нажимается.

### Qrator

| Ответ | `kind` |
|---|---|
| 401 с `Set-Cookie: qrator_jsr=` или скриптом `/__qrator/` на странице | `challenge` |
| 403 с `X-Qrator-Validate-Result: captcha` (и свежим `X-Qrator-Token`) | `captcha` — картинка |
| 403 с любым другим вердиктом, или 418, или 420 | `captcha` — чекбокс |
| 403 от `/__qrator/validate` **без** заголовка вердикта | `no-verdict` |
| `Server: QRATOR` на обычном ответе | `None` — он стоит и на 200 |

`no-verdict` — различие, за которое полевой отчёт заплатил полднём. Снаружи оба
отказа — «403». Один значит *тебя оценили и отправили на капчу*: браузерный
403 там нёс вердикт и новый токен. Другой — *присланное не смогли прочитать*:
собственный запрос проверки пришёл голым, без вердикта, без токена,
`content-length: 0`. Различает их только заголовок. `no-verdict` не решаем —
браузер бы прошёл; сломался запрос, который собрали вы.

Путь `/__qrator/` — метка вендора сам по себе: у голого 403 другая метка
только `Server`, а его может переписать прокси по дороге.

**Готовое решение:** `challenge` и `captcha` отдаются решателю сессии, как
любые другие. **Что `BrowserSolver` проходит настоящую проверку Qrator, этот
проект не проверял**: правила выше замерены, прохождение — нет. Чекбокс сам не
нажимается — решатель жмёт только рамки Cloudflare, — так что он ждёт человека
у окна. Где нужен отдельный решатель для Qrator, встаёт свой (раздел 3.4).

### DataDome

| Ответ | `kind` |
|---|---|
| заголовок `x-datadome` или `x-datadome-cid`, и `captcha-delivery.com` на странице | `captcha` |
| заголовок без неё | `block` |
| `captcha-delivery.com` на странице и выставленная кука `datadome` | `captcha` |

**Готовое решение:** `BrowserSolver`, у которого для DataDome кука прохода —
`datadome`. Слайдер ждёт человека у окна. На самом DataDome не проверялось.

### HUMAN (PerimeterX)

`_pxAppId` или `px-captcha` на странице → `captcha`. «Нажми и держи» ждёт
человека у окна `BrowserSolver`; пробуется любое изменение кук. На самом
HUMAN не проверялось.

### Akamai

`sec-if-cpt-container` или `/_sec/cp_challenge/` на странице → `challenge`;
`Server: AkamaiGHost` с «Access Denied» → `block`. Интерстишел выполняется в
браузере сам. На самом Akamai не проверялось.

### Imperva (Incapsula)

`_Incapsula_Resource` на странице → `challenge`; «Incapsula incident ID» →
`block`. На самом Imperva не проверялось.

### Kasada

429 с любым заголовком `x-kpsdk-*` → `challenge`. На самой Kasada не
проверялось.

### Ответ, который `r.challenge` не узнаёт

403 с `r.challenge is None` — это либо отказ самого сайта (истёкшая сессия,
нет прав), либо вендор, чьих меток пакет не знает. `r.headers` и первые строки
`r.text` обычно говорят, что именно. Отчёта с двумя ответами рядом —
браузерным и библиотечным, как в отчёте о Qrator, — достаточно, чтобы добавить
вендора.

## 3. Готовые решения

### 3.1 `BrowserSolver`: проверка — в установленном здесь Chrome

```python
solver = curlpro.BrowserSolver()
s = curlpro.Session(**solver.session_options(), solver=solver)
r = s.get(url)    # проверка → браузер проходит её → его куки → запрос снова
```

**Что он делает.** Сессия с `solver`, встретив решаемую проверку, отдаёт её:
решатель открывает страницу в Chrome (или Edge), установленном на машине,
ждёт, пока проверка пройдёт, отдаёт сессии куки, и сессия посылает запрос
снова. Вы получаете страницу за воротами.

**Почему его не ловят как автоматизацию.** Chrome запускается с URL в
командной строке, как будто его открыл человек. Весь трафик DevTools — это
собственная точка браузера: его версия, вкладки, куки. Ни к одной странице не
подключаются, `Runtime.enable` не отправляется, ни один наш скрипт на
странице не выполняется, `--enable-automation` нет: меток, которые выдают
Playwright и Puppeteer, нет. `navigator.webdriver`, который порт DevTools в
Chrome 154 включает, выключен обратно — без плашки «неподдерживаемый флаг»,
которая выросла бы рамкой окна на 56 px. Флаги, облегчающие браузер, замерены
по одному — не меняют ничего, что читает страница, — и все вместе против всех
340 значений, которые пишет `scripts/fpcapture.py`.

**Почему потом проходит сессия.** Пропуск выдан отпечатку браузера, а сессия
на проводе *и есть* этот браузер: `session_options()` возвращает профиль
версии установленного браузера и устройство его точной сборки —
`impersonate="chrome-154-windows"`,
`device="Windows 10 22H2, Chrome 154.0.8037.93"`. Сессию другой версии решатель
отвергает с `ConfigurationError`, а не отправляет с кукой, которой
противоречит её собственный ClientHello. Сборка, которой ещё нет в списке
устройств профиля, — Chrome обновляется сам за ночь — получает новейшее
устройство того же релиза ОС с собственной сборкой браузера.

**Что проходит само, а что требует клика или человека.**

- Проверка, которая идёт без участия человека, без него и проходит. Запрос
  повторяется в момент, когда появляется кука прохода вендора (`cf_clearance`,
  `datadome`), и при любом другом изменении кук — не чаще раза в 2 с: у сайта
  за Turnstile бывают собственные ворота со своей кукой.
- **Чекбокс Turnstile нажимается за вас.** Если проверка не прошла сама за
  `click_after` (2,5 с), к вкладке подключаются только на этот момент:
  инспектор находит рамку проверки Cloudflare — и в закрытом shadow root, — а
  мышь идёт к ней по кривой, с человеческой скоростью, через домен Input
  DevTools, чьи события страница получает как доверенные. По-прежнему без
  `Runtime` и без скрипта. Не больше трёх кликов, с паузой 8 с. Отслеживание
  перекрытия окон Windows выключено, так что окно под другим окном
  принимает клик сразу.
- **Всё остальное, что требует человека, ждёт его** в окне браузера:
  картинка, слайдер, «нажми и держи», чекбокс другого вендора. Ради окна
  `headless=False` и стоит по умолчанию.

**Замерено:**

| Проверка | Результат |
|---|---|
| JS-проверка за `cf-mitigated` (стенд) | пройдена за 2,1–2,4 с |
| настоящий виджет Turnstile Cloudflare, тестовый ключ «всегда пропускать» | пройден за 3,7 с |
| Turnstile, тестовый ключ «всегда просить чекбокс» | пройден за 4–7,5 с с кликом, без клика — никогда |
| nowsecure.nl (настоящий Cloudflare) | `cf_clearance` за 3 с |
| пять решений с браузером, держащимся открытым (`keep_open=True`) | медиана 1,55 с против 2,64 с с браузером на каждое |

**Параметры:**

| Параметр | По умолчанию | Значение |
|---|---|---|
| `headless` | `False` | headless-Chrome пишет `HeadlessChrome` в User-Agent, такого нет ни в одном профиле — решатель отвергает расхождение; а капче нужно окно |
| `profile_dir` | нет | хранить профиль браузера между решениями: браузер, который уже бывал на сайте, — вернувшийся посетитель. Без него каждое решение начинается с чистого профиля |
| `keep_open` | `False` | держать один браузер между решениями (раздел 3.2) |
| `click` | `True` | нажимать чекбокс Turnstile; `False` оставляет его человеку |
| `click_after` | 2,5 | сколько секунд проверка получает, чтобы пройти сама, до клика |
| `timeout` | нет | самое долгое ожидание решения, если оно короче 90 с сессии |
| `poll` | 0,5 | как часто читаются куки |
| `executable` | найденный | какой браузер запускать; то же делает `CURLPRO_CHROME` в окружении |

**Что он берёт у сессии.** Прокси — прокси с логином идёт через локальный
пересыльщик, который добавляет учётные данные и пропускает туннель нетронутым,
потому что Chrome не принимает их в командной строке; WebRTC держится на
прокси. Языки — записываются в профиль браузера, как их выставляет человек.
Часовой пояс личности (раздел 3.3).

**Как сессия им пользуется.** Запросы к одному сайту ждут одного решения:
десять запросов разом, упёршихся в одни ворота, — это один браузер, а не
десять. `AsyncSession` решает вне цикла событий. `block`, `rate-limit` и
`no-verdict` решателю не отдаются никогда. Решение, которое не прошло, бросает
`ChallengeError` со страницей проверки в `.response`. Потоковый запрос
решателю не отдаётся — сначала пройдите ворота одним обычным запросом, потом
стримьте с куками в банке.

**Что ему нужно.** Установленный Chrome или Edge, и больше ничего: с DevTools
он говорит через WebSocket из стандартной библиотеки.

### 3.2 Один браузер на много решений

```python
with curlpro.BrowserSolver(keep_open=True) as solver:
    for url in urls:
        with curlpro.Session(**solver.session_options(), solver=solver) as s:
            s.get(url)
```

Один браузер на прокси и языки — оба принадлежат браузеру и задаются при его
запуске, — и каждое решение в новой вкладке, по одному, с предварительно
очищенными куками. Не контекст браузера на решение: замерено на Chrome 154 —
страница в контексте, созданном через DevTools, просит языки по умолчанию для
локали интерфейса, а не `Accept-Language` сессии. Закрывается
`solver.close()` или блоком `with`. С `profile_dir` не сочетается.

### 3.3 Один посетитель: личность

Браузер за немецким адресом, который сообщает часовой пояс и языки другой
страны, — противоречие, которое скрипты отпечатков сверяют с IP в одну строку.

```python
ident = curlpro.Identity.lookup(proxy)            # где выходит прокси (ipinfo.io, через него)
ident = curlpro.Identity.for_country("DE")        # или без сети: de-DE, de, en-US, en; Europe/Berlin
s = curlpro.Session(**solver.session_options(), proxy=proxy, identity=ident, solver=solver)
```

Сессия шлёт языки личности как `Accept-Language` с весами Chrome, а браузер,
который решает, держит те же языки и пояс — на странице, в её `Date`, в
выделенном, общем и сервис-воркерах (замерено на стенде). `lookup()` — это
единственный сетевой вызов, и делается он только по просьбе.

### 3.4 Свой решатель

Любой объект с `solve(request) -> Solution | None` — решатель. Это место для
решателя под конкретного вендора, для кук прохода, полученных где-то ещё, для
человека в другом окне.

```python
from urllib.parse import urlsplit
import curlpro

class StoredClearance:
    """Отдаёт сессии куки прохода, полученные другим процессом."""

    def __init__(self, store):
        self.store = store

    def solve(self, req: curlpro.SolveRequest):
        cookies = self.store.get(urlsplit(req.url).hostname)
        if cookies and req.verify(cookies):
            return curlpro.Solution(cookies, req.user_agent, "stored")
        return None                               # → у вызывающего ChallengeError

s = curlpro.Session("chrome-154-windows", solver=StoredClearance(my_store))
```

Что получает решатель (`SolveRequest`):

| Поле | Значение |
|---|---|
| `challenge` | `Challenge`: вендор, вид, метки |
| `url` | что открыть — для GET сам URL запроса, иначе страницу, с которой он сделан, иначе корень сайта |
| `impersonate`, `user_agent`, `accept_language` | сессии; браузер, который решает, должен быть тем же |
| `proxy` | прокси, через который шёл запрос, `""` без него — пропуск принадлежит адресу |
| `timezone` | часовой пояс личности, `""` — собственный машины |
| `verify(cookies)` | загружает куки в сессию, посылает запрос снова, говорит, прошёл ли он |
| `timeout` | сколько ждёт сессия (90 с) |

Кука — словарь: `name`, `value`, `domain`, `path`, `host_only` и, при
необходимости, `expires`, `secure`, `http_only`, `same_site`, `partition`.
Верните `Solution(cookies, user_agent, browser)` после `verify`, сказавшего
«да», или `None`. Гарантии сессии действуют для любого решателя: одно решение
на сайт за раз, async — вне цикла, неудача — `ChallengeError`.

### 3.5 Руками: сессия в своём браузере

```python
with curlpro.Session(**curlpro.BrowserSolver().session_options()) as s:
    with s.browser(url) as b:        # её прокси, личность и куки, выставленные до загрузки страницы
        b.wait()                     # человек проходит проверку; закрытое окно завершает ожидание
    s.get(url)                       # куки вернулись
```

Для проверки, которую ничто не проходит само, или чтобы увидеть, что шлёт
браузер там, где запрос библиотеки падает. `sync()` возвращает куки в любой
момент, `local_storage(origin)` читает хранилище страницы, а выход из блока
возвращает всё.

## 4. Рецепты

| Видите | Это | Делайте |
|---|---|---|
| 403, `r.challenge` — `None` | отказ самого сайта или вендор, которого пакет не знает | смотрите `r.headers` и начало `r.text`; о новом вендоре — отчёт с браузерным ответом рядом с вашим |
| `cloudflare` / `challenge` | JS- или управляемая проверка | `solver=BrowserSolver()` |
| `cloudflare` / `challenge`, затем чекбокс Turnstile | интерактивный Turnstile | то же — чекбокс нажимается |
| `datadome` / `captcha`, `human` / `captcha` | слайдер, «нажми и держи» | `BrowserSolver` с окном и человек; или свой решатель |
| `qrator` / `challenge` | его 401 и скрипт | отдать решателю; `BrowserSolver` на нём не проверен |
| `qrator` / `captcha` | оценён и отправлен на картинку или чекбокс | человек у окна `BrowserSolver` или свой решатель |
| `qrator` / `no-verdict` | ваш запрос проверки не смогли прочитать | это не оценка вас: исправьте запрос — сравните его с браузерным (`s.browser()`, `s.headers_for(method, url)`) |
| любой `block` | решение об адресе или запросе | другой адрес, медленнее темп; решатель не поможет |
| `cloudflare` / `rate-limit` | 1015 | сбавить темп; `Session(retries=3)` повторит 429 и подождёт, сколько сказал его `Retry-After` (`respect_retry_after` включён по умолчанию — но `retries` по умолчанию 0, так что без просьбы ничего не повторяется) |
| `ConfigurationError: open the session as …` | профиль сессии — не версия установленного браузера | открывать с `**solver.session_options()` |
| `ChallengeError: … the solver did not get past it` | решение не уложилось во время или ни разу не подтвердилось | человек у окна, больше `timeout`, `profile_dir` для вернувшегося посетителя |
| проверка на каждом запросе пачки | | одно решение на сайт: остальные ждут его и берут его куки |

## 5. Что проверено, а что нет

| Утверждение | Статус |
|---|---|
| Cloudflare узнаётся по `cf-mitigated` | документированная метка вендора; покрыто тестами |
| `BrowserSolver` проходит JS-проверку и Turnstile, нажимая его чекбокс | замерено на стенде с настоящим виджетом Turnstile и тестовыми ключами Cloudflare |
| `BrowserSolver` получает `cf_clearance` от настоящего Cloudflare | замерено на nowsecure.nl |
| Браузер не оставляет меток автоматизации, которые может прочитать страница | замерено: `webdriver` — false, плашки нет, 340 значений флаги не меняют |
| Правила Qrator | сняты на проводе полевым отчётом; воспроизведены на стенде |
| `BrowserSolver` проходит настоящую проверку Qrator | **не проверено** |
| DataDome, HUMAN, Akamai, Imperva, Kasada узнаются | по известным меткам их страниц; **здесь не замерялось** |
| `BrowserSolver` проходит их проверки | **не проверено** |

## 6. Чего он не будет делать

- **Отправлять проверку в сервис решения капч.** Ни в пакете, ни опцией.
  Свой решатель — ваше дело.
- **Переписывать проверку вендора.** Проверка — программа, которая измеряет
  браузер, в котором работает; переписанная копия проигрывает каждый раз,
  когда вендор выпускает новую.
- **Работать headless.** User-Agent headless-Chrome пишет `HeadlessChrome`,
  которого нет ни в одном профиле; решатель скорее откажет, чем покажет
  противоречие.
